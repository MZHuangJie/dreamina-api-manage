# 多账号调度与失败重试

## 1. 调度策略

派活时按策略挑账号，可在界面上切换（也支持单次请求临时指定）。

| 策略 | 行为 | 适用 |
| --- | --- | --- |
| `least_failures`（默认） | 失败次数最少优先，同分时挑最久没用的 | 综合最稳 |
| `round_robin` | 轮流用 | 想让各账号用量均匀 |
| `most_credit` | 积分最多优先 | 想把某个号先跑空 |
| `active` | 只用「当前账号」 | 手动控制 / 调试 |

无论哪种策略，以下账号一律跳过：

- 已停用
- 登录态失效（`health = expired`）
- 仍在冷却期内（`cooldown_until` 未到）

## 2. 失败记账

| 事件 | 效果 |
| --- | --- |
| 生成成功 | `success_count + 1`，**失败计数清零**，解除冷却 |
| 生成失败 | `failure_count + 1`，进入冷却（默认 60 秒），记录错误信息 |
| 登录态失效 | 额外标记 `health = expired`，**彻底退出调度**，直到手动恢复或探活成功 |
| 探活成功 | 刷新积分与昵称，清除失效标记和冷却 |

冷却的意义：一次偶发失败（比如代理抖动）不该让账号被永久冷落，
但也不该立刻又被挑中，否则重试会一直撞同一个坏号。

## 3. 失败重试与自动换号

一次生成最多尝试 **3 个账号**（`MANAGER_MAX_ATTEMPTS`）。

```
挑账号 A → 提交 ──成功──→ 轮询 → 出图
            │
            └─失败─→ 记 A 的账 ─→ 换账号 B → 提交 ──成功──→ …
                                    │
                                    └─失败─→ 记 B 的账 ─→ 换账号 C → …
```

换号时**已试过的账号会被排除**，不会在原地打转。

### 什么情况才换号

这是重试逻辑里最需要想清楚的部分：

**换号有意义**（会自动切换）

- 登录态失效、权限不足 → 这个号的凭据不行了
- 积分/权益不足 → 这个号没额度了，换一个有额度的
- 账号没有 workspace → 这号还没在网页端启用过
- 代理连不上、超时、DNS 失败 → 这个出口有问题
- `shark not pass reject` → 风控拦截，换个账号/出口常常能过

**换号没用**（直接失败，不浪费其它账号）

- **内容审核不通过** —— 同一个 prompt 换哪个号都会被同样拒绝。
  盲目重试只会白白烧掉其它账号的额度，还在平台侧留下一串违规提交记录。
- 参数错误、提示词为空 —— 代码问题，不是账号问题。

### 一个重要的边界：提交之后不重试

**只有「提交成功之前」的失败才会换号。**

一旦平台返回了 `history_record_id`，任务就已经在平台上跑起来了。
此时换号重提会产生**两份**生成——既浪费额度又在平台侧留下多余记录。

所以提交之后的失败（比如轮询超时）不会重试，而是直接暴露给调用方，
并把 `history_record_id` 留在记录里，需要的话可以人工去平台侧查。

实现上用 `preSubmitError` 包装来标记这个边界，见 `internal/tasks/tasks.go`。

## 4. 可观测性

重试过程会写进操作日志，在界面上能看到：

| 事件 | 含义 |
| --- | --- |
| `generate.switch` | 换号了，日志里有换到哪个账号 |
| `generate.no_retry` | 决定不重试，以及**为什么**（审核 / 已提交 / 非账号问题） |
| `generate.failed` | 最终失败 |

生成记录的 `progress` 字段会实时显示 `第 N/M 次尝试 · 账号「X」`，
所以在界面上能直接看到换号过程，不用翻日志。

## 5. 配置

| 环境变量 | 默认 | 说明 |
| --- | --- | --- |
| `MANAGER_MAX_ATTEMPTS` | 3 | 一次生成最多尝试几个账号 |
| `MANAGER_FAILURE_COOLDOWN_MS` | 60000 | 失败后的冷却时长 |
| `MANAGER_HEALTH_INTERVAL_MS` | 1800000 | 保活巡检间隔（30 分钟） |

## 6. 保活巡检

后台定时（默认 30 分钟）并发探活所有启用账号：

- 刷新积分与昵称
- 登录态失效的标记 `expired`，自动退出调度
- 恢复正常的账号重新参与调度

启动时会先跑一次，之后按间隔循环。
